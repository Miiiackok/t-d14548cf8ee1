# 旅行日历部署

这是可部署到 GitHub Pages 的旅行日历。发布目录应包含静态前端、字体、PDF 查看器、图标和公开地名索引。测试文件、账号密码和私人行程迁移包应留在 Git 仓库之外。

1. 在目标 Supabase 项目中运行 `schema.sql`。它建立旅行、行程数据和私人附件空间。
2. 配置邮箱和密码登录，把原 GitHub Pages URL 设为允许的返回地址。在只供自己使用时关闭公开注册，并先建立自己的账号。未来开放注册时，同时更新服务器注册设置和前端的 `allowRegistration`。
3. 给 `site/config.js` 填写项目 URL 和 **Publishable key**。任何管理密钥或旧网站密码都无需加入网站文件。把 `migrationOwner` 设为原网站拥有者的账号 UUID，供迁移入口核对账号。
4. 在测试部署中用两个账号核验登录和隔离。登录原网站拥有者账号后，在原浏览器和原网址选择私有迁移包，迁入纽约行程与该浏览器中的旧附件。手机主屏幕应用和桌面浏览器如有不同文件，需要分别从原有保存位置迁入。迁移会保留已写入的同名记录，第二次运行可以继续处理第一次未完成的记录。
5. 在两台设备用同一账号核验行程修改、照片和 PDF，再发布。当前版本联网同步，断网时可继续看已加载的页面。

国家和城市搜索使用随前端一起发布的 [GeoNames 数据](https://www.geonames.org/export/)，按 CC BY 许可使用。索引根据国家与地区资料和城市资料生成，整理了中英文别名。用户搜索内容在浏览器内筛选。
